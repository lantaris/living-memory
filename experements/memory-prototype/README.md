# memory-prototype

Минимальный прототип трёхслойной памяти для диалогового ИИ. Вместо хранения всей
истории сообщений ассистент ведёт сжатую «живую модель» пользователя и диалога.

## Идея

Проблема не в размере контекстного окна, а в отсутствии иерархии и сжатия.
Память делится на три слоя:

| Слой | Файл | Что хранит | Как меняется |
|------|------|-----------|--------------|
| Ядро | `memory/core.json` | кто пользователь, предпочтения, цели | почти не меняется |
| Задачи | `memory/tasks.json` | открытые темы: что решено, что осталось | средне |
| Оперативка | `memory/recent.jsonl` | последние 10 сообщений как есть | быстро |

Плюс `memory/index.db` (SQLite) — полная история для восстановления деталей,
которые не попали в конспект.

## Запуск

Зависимостей нет — только Python 3.10+ и стандартная библиотека.

```bash
cd memory-prototype
python3 test_scenario.py
```

Сценарий проигрывает 20 сообщений диалога (+1 приватное), сжимает оперативку при
переполнении, повторяет диалог 3 раза и проверяет 24 утверждения: ядро и задачи
обновляются, оперативка не растёт, приватное не сохраняется, свежие факты доступны,
старые — живут в конспекте, контекст не растёт вместе с историей.

## Тесты границ сжатия

```bash
python3 test_loss_conflict.py --provider mock      # без LLM
python3 test_loss_conflict.py --provider opencode  # реальная LLM
```

- **Тихая потеря**: мимоходный факт не попадает в конспект, но остаётся в
  `index.db` — потеря обратима через `store.search`.
- **Конфликт фактов**: «Предпочитаю Python» → «Перешёл на Rust». `deep_merge`
  накапливает оба значения; реальная LLM помечает смену («switched from
  Python»), мок — нет. Результаты обоих прогонов — в `NOTES.md` §6.

## Тесты автономности агента

```bash
python3 test_session.py --provider mock|opencode [--tests 1|2|3]
python3 test_model_swap.py --modes A|B|C
```

- **Flush** (`--tests 1`): `flush()` досжимает оперативку при закрытии сессии;
  новая сессия видит факты через ядро/задачи, а не только через поиск.
- **Журнал потерь** (`--tests 2`): вытесненные и не использованные сжатием
  реплики пользователя попадают в `memory/loss_log.jsonl` — потеря видна и
  обратима (пометка `indexed`).
- **Pending** (`--tests 3`): неуверенные факты из патча сжатия идут в
  `memory/pending.jsonl`; `resolve_pending` подтверждает (факт в ядро/задачи)
  или отклоняет (запись остаётся как аудит).
- **Смена модели** (`test_model_swap.py`): A — мок-диалог + мок-сжатие;
  B — живой диалог LLM + мок-сжатие; C — мок-диалог + LLM-сжатие. Все три
  сохраняют ключевые факты; разница — в `NOTES.md` §8.

## Retention-тест (только реальная LLM)

```bash
python3 test_retention.py --run 1|2|3   # прогон: диалог 104 сообщения, 20 фактов
python3 test_retention.py --report      # сводные таблицы
```

Режимы: A — полная история, B — живой конспект, C — гибрид (+20 сообщений).
После слоя нормализации: B стоит 67% от A (было 95%), конспект стабилен
(не растёт с длиной), точность на важных фактах — на уровне полной истории
(14.0 из 15 против 14.0), мимоходные детали честно теряются («не знаю»).
Полные таблицы и вывод — `NOTES.md` §9 и §10.

## Тесты нормализации

```bash
python3 test_normalization.py --provider mock|opencode [--tests unit|e2e]
```

- **UNIT** (без LLM): грязный патч (длинные строки, `style`, мусорные ключи,
  дубли тем, 12 задач) → лимиты, фильтры категорий, дедупликация, капы 10+10,
  всё отклонённое — в `loss_log.jsonl` с причиной.
- **E2E**: диалог-провокация (длинное решение, «отвечай коротко», похожие темы)
  → после сжатия инварианты конспекта соблюдены на моке и реальной LLM.

## Использование без теста

```python
from store import MemoryStore
from llm import get_default_provider
from compress import maybe_compress
from inject import build_system_prompt

store = MemoryStore(".", recent_limit=10)
provider = get_default_provider()

store.append_message("user", "Привет, меня зовут Иван")
maybe_compress(store, provider)          # сжатие при заполнении оперативки
prompt = build_system_prompt(store)      # это идёт в LLM вместо всей истории
store.search("Иван")                     # вернуть деталь из полной истории
```

## Провайдеры LLM

Сжатие абстрагировано интерфейсом `LLMProvider` (`llm.py`):

- `MockProvider` — детерминированная эвристика на русском языке. Используется в
  тестовом сценарии, работает офлайн и не требует API. Проверяет механику, а не
  качество сжатия.
- `OpencodeCLIProvider` — реальный LLM через `opencode run` (включается переменной
  `MEMORY_LLM_PROVIDER=opencode`, модель задаётся `MEMORY_LLM_MODEL`).

```bash
MEMORY_LLM_PROVIDER=opencode python3 test_scenario.py
```

## Результат проверки

На 60 сообщениях диалога полная история занимает ~6900 символов, контекст — ~2200
(31%), при этом имя из первого сообщения, решения и цели доступны модели через
ядро и задачи, а любая деталь возвращается из `index.db`. Сессия закрывается через
`flush()` без потери хвоста; потери user-реплик видны в журнале и обратимы;
неуверенные факты уходят в очередь подтверждения. Механизм работает и на моке, и
на реальной LLM; ограничения — в `NOTES.md` §8.
